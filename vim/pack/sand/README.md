# My own vim plugins - no plugin manager required

Vim 8+ has a built-in package system. Anything under

    ~/.vim/pack/<any-name>/opt/<plugin-name>/

is a plugin. Vim finds it on its own. There is nothing to install, nothing to
download, no `git clone` at runtime - which is exactly why this works on
machines where plugin managers are not an option.

`start/` vs `opt/`:

  - `pack/sand/start/foo/` loads automatically at startup.
  - `pack/sand/opt/foo/`   loads only when you say `packadd! foo`.

Everything here lives in `opt/` on purpose, so the `if getenv("SAND")` guard in
`vimrc` stays in control of what gets loaded.

## The plugins

| plugin          | what it gives you                                  | help              |
|-----------------|----------------------------------------------------|-------------------|
| `tmux-navigate` | `<A-hjkl>` across vim windows *and* tmux panes     | `:h tmux-navigate`|
| `projectfind`   | `:find` shortcuts from a path dictionary            | `:h projectfind`  |
| `gitdiff`       | `:GitDiff [rev]` against any revision               | `:h gitdiff`      |
| `format`        | `:Format` that cannot eat your buffer               | `:h format`       |
| `keyclue`       | popup showing what can follow a prefix key          | `:h keyclue`      |
| `pick`          | fuzzy `:Files`, live `:Grep`, `:Buffers`, `:Lines`  | `:h pick`         |
| `harpoon`       | a few files per project, jumped to by number        | `:h harpoon`      |

## Layout of one plugin

    pack/sand/opt/tmux-navigate/
      plugin/tmux_navigate.vim      sourced at startup: commands + mappings
      autoload/sand/tmux.vim        sourced on first call: the actual work
      doc/tmux-navigate.txt         :help tmux-navigate
      doc/tags                      generated by :helptags (committed, so the
                                    folder works as-is when copied)

The three directories map to three jobs:

  - `plugin/` is the entry point. Keep it cheap - it runs on every startup.
    Guard it with `if exists('g:loaded_x') | finish | endif` so sourcing it
    twice is harmless.
  - `autoload/` holds the implementation. A function named `sand#tmux#navigate`
    lives in `autoload/sand/tmux.vim` and is only read from disk the first time
    it is actually called. Free lazy loading.
  - `doc/` is optional but nice - real `:help` for your own tools.

## Turning things off

Three levels, from softest to hardest:

1. **Keep the commands, drop the key bindings.** Every plugin honours a
   `g:<name>_no_mappings` flag, set *before* the `packadd!` loop in `vimrc`:

       let g:pick_no_mappings = 1
       let g:format_no_mappings = 1

   You then bind what you want yourself, via the `<Plug>` maps:

       nmap <leader>F <Plug>Format

2. **Do not load the plugin at all.** Comment its name out of the list in
   `vimrc`. Nothing is sourced, nothing is defined, zero cost.

3. **Delete the folder.** `rm -rf ~/.vim/pack/sand/opt/<name>`.

`keyclue` additionally has a runtime switch, because it is the one plugin that
changes how an existing key behaves: `:KeyClueDisable`, `:KeyClueEnable`,
`:KeyClueToggle`.

## Adding a new plugin

    mkdir -p ~/.vim/pack/sand/opt/myplugin/{plugin,autoload,doc}

Write `plugin/myplugin.vim`, then add its name to the list in `vimrc`.
Regenerate help tags after editing a doc file:

    :helptags ~/.vim/pack/sand/opt/myplugin/doc

## Using it at work

Copy the plugin folders into `~/.vim/pack/sand/opt/` on the work machine. That
is the whole install. The same trick works for third-party plugins too: a
plugin repo is just a folder of vimscript, so copying one in by hand is
equivalent to what a plugin manager would have done.

Everything here is plain vimscript with feature guards (`has('popupwin')`,
`exists('*matchfuzzy')`), so an older vim on a work box degrades rather than
errors. `pick` is the one that wants a recent-ish vim: it needs `+popupwin`,
which means vim 8.2 or newer.
